# 通知功能测试指南

## 前提条件

- 已安装打包后的 `撷风拾影_0.3.3_x64-setup.exe`
- 抖音 Cookie 已配置且有效（否则下载会失败，无法测试完成通知）
- 确保 Windows 系统通知已开启（Windows 设置 → 系统 → 通知和操作 → 确保"撷风拾影"的通知开关为开启）

## 测试步骤

### 1. 确认通知配置默认开启

1. 启动应用
2. 点击左下角 ⚙️ 设置
3. 展开 **"通知设置"** 卡片
4. 确认以下默认值：
   - ✅ 任务完成弹窗通知 → **开启**
   - ✅ 任务完成音效 → **开启**
   - ✅ 音效选择 → **默认音效**
   - ✅ 音效音量 → **50%**

> 如果之前修改过配置，可以先点击底部的"恢复初始设置"，或者手动确认开关状态。也可以直接跳过此步骤，在测试中观察默认行为。

### 2. 下载单个视频 → 验证完成通知

**操作：**
1. 进入 **批量抓取** 页
2. 粘贴一个抖音视频链接（如 `https://www.douyin.com/video/xxxx`）
3. 点击"解析" → 点击"下载选中"
4. 切换到 **下载任务** 页，等待下载完成

**预期结果（逐条验证）：**

| 检查项 | 预期行为 | 判断方法 |
|--------|---------|---------|
| ① 进度条变绿 | 下载完成后进度条变为绿色，显示"完成" | 肉眼观察界面 |
| ② Toast 提示 | 界面右下角弹出绿色 Toast 提示"任务下载完成"或"一项下载任务已完成" | 观察界面右下角 |
| ③ 音效播放 | 下载完成瞬间播放一声短促的上升双音（C5→E5） | 用耳朵听 |
| ④ 系统通知 | Windows 右下角弹出 Toast 通知"下载任务完成"或"下载完成" | 观察 Windows 通知区域 |

> **注意：** 开发模式（`tauri dev`）下系统通知会显示为"PowerShell"名称且不会存入通知中心，这是已知限制。打包安装后通知会显示为"撷风拾影"并可存入通知中心。

### 3. 下载多个视频 → 验证聚合通知

**操作：**
1. 在批量抓取页一次性解析多个视频链接（3-5 个）
2. 点击"下载全部"
3. 切换到下载任务页，等待所有下载完成

**预期结果：**
- 每个单项完成时：弹出 Toast + 播放音效（第 2、3...N 个）
- 全部完成时：弹出系统通知"下载任务完成：N/N 项下载成功" + Toast + 音效

### 4. 测试音效切换

**操作：**
1. 进入设置 → 通知设置
2. 将音效选择改为 **"轻柔"**，点击"保存"
3. 下载一个视频，听音效是否变为柔和的单音上行（A4→C5）
4. 再将音效选择改为 **"活泼"**，保存后下载一个视频
5. 听音效是否变为欢快的三音上行（C5→E5→G5）

### 5. 测试通知开关

**操作：**
1. 进入设置 → 通知设置
2. 关闭"任务完成弹窗通知"，点击"保存"
3. 下载一个视频，确认系统通知不再弹出，但 Toast 和音效仍然正常
4. 关闭"任务完成音效"，点击"保存"
5. 下载一个视频，确认音效不再播放

### 6. 测试自定义音效（可选）

**操作：**
1. 准备一个 .wav 或 .mp3 文件
2. 进入设置 → 通知设置
3. 音效选择改为"自定义 MP3" 或 "自定义 WAV（原生）"
4. 点击"选择文件"选取音频文件
5. 点击"保存"
6. 下载一个视频，确认播放的是自定义音效

## 故障排查

### 现象 1：Toast 不出现

可能原因：
- 前端 JavaScript 异常 → 打开开发者工具（Tauri 中按 F12）查看 Console 是否有报错
- 浏览器引擎限制 → 重启应用再试

### 现象 2：音效不播放

可能原因：
- Web Audio API 被浏览器 autoplay 策略阻止 → 在下载前先点击界面任意位置（如点击"下载"按钮本身就已建立用户交互上下文）
- 音量设置为 0 → 检查音量滑块
- 音效选择为"自定义"但未设置文件 → 检查音效选择

### 现象 3：系统通知不出现

可能原因：
- Windows 通知权限被拒绝 → Windows 设置 → 系统 → 通知和操作 → 搜索"撷风拾影" → 确保通知已开启
- 通知开关已关闭 → 检查设置
- 通知在开发模式（tauri dev）下显示为"PowerShell"是正常现象，不影响功能

### 现象 4：进度条变绿但无任何通知

可能原因：
- WebSocket 连接断开（前端降级为 REST 轮询，轮询更新 UI 但不触发通知）
- 修复后：理论上应同时处理 `item_completed` 消息和 `progress` 消息的完成状态，确保通知发送

> 如果以上排查均无效，请检查应用日志：`%APPDATA%\XieFengShiYing\logs\app.log`，搜索 `task_completed` 或 `item_completed` 关键词，确认后端是否正常广播了完成事件。

## 判断标准速查表

| 测试项 | 通过条件 |
|--------|---------|
| 基本通知 | 下载完成时有 Toast 提示、音效播放、系统通知弹出 |
| 音效切换 | 切换"轻柔"/"活泼"后音效明显不同 |
| 通知开关 | 关闭后对应类型的通知不再出现 |
| 无通知不触发 | 已有任务打开页面时不会弹出通知（只对新完成的任务触发） |
| 聚合通知 | 多任务下载时每个完成项和全部完成时均有通知 |
