## 1. DownloadPage onWsMessage：状态过渡检测

### 现状（frontend/src/pages/DownloadPage.tsx 第 41-50 行）
```tsx
const onWsMessage = useCallback(
  (msg: WsMessage) => {
    if (msg.type === "progress" && msg.updates) {
      for (const update of msg.updates) {
        applyProgressUpdate(update);
      }
    }
  },
  [applyProgressUpdate],
);
```

### ProgressUpdate 数据结构（frontend/src/hooks/useWebSocket.ts 第 7-14 行）
```ts
export interface ProgressUpdate {
  task_item_id: number;
  downloaded_bytes: number;
  total_bytes: number;
  progress: number;
  status: string;      // <- 变化的关键字段
  aweme_id: string | null;
}
```

### taskStore.applyProgressUpdate 现状（taskStore.ts 第 129-143 行）
- 根据 update.status 直接覆盖 item.status
- completed/processing 时 progress 强制为 100
- **没有返回旧状态，也不感知"状态变化"** —— 只是无差别覆盖

### 状态过渡检测方案（供工程师实现参考）
检测"非终态 -> completed/failed 的过渡"，关键思路：**在 applyProgressUpdate 应用更新之前，比较该 item 的旧状态**。

| 方案 | 描述 | 优缺点 |
|---|---|---|
| **A. 在 onWsMessage 中检测**（推荐） | 在 for 循环里调 applyProgressUpdate 前，先从 taskStore 的 items 中按 task_item_id 找到旧 item，判断 旧状态非终态 && 新状态为 completed/failed，则触发通知 | 最直观；与 UI 解耦；需从 store 读 items（useTaskStore.getState().items） |
| **B. 在 applyProgressUpdate 中返回变化信息** | 修改 store 方法返回 { transitioned: boolean, prevStatus, newStatus, item } | 通知逻辑集中在 store，但 store 本来纯粹管理数据，处理通知副作用不太合适 |
| **C. 监听 store 变化** | 用 zustand 的 subscribe 监听 items 变化，对比前后状态 | 全局生效，但会错过"同一状态多次更新"的噪音过滤，且需要额外去重 |

**推荐方案 A 的具体逻辑**：
1. 对每个 update，取 update.task_item_id
2. 从 taskStore 中查找现有 item（useTaskStore.getState().items.find(i => i.id === update.task_item_id)）
3. 若旧 item 存在：判断 !isTerminal(旧状态) && (update.status === "completed" || update.status === "failed")
4. 触发相应通知（completed -> 成功弹窗+成功音效；failed -> 失败弹窗+失败音效）
5. 再调用 applyProgressUpdate
6. 若旧 item 不存在（首次加载/轮询期间新增），跳过通知（避免对已有终态项误报）

### 重要注意事项：轮询降级路径
- WebSocket 断开时 DownloadPage 会启用 **2 秒 REST 轮询**（第 54-76 行），轮询走 loadTasks() -> 直接替换 items，**不走 applyProgressUpdate，也没有过渡检测**。
- 若通知只挂在 WebSocket 路径上，断线期间完成的任务不会通知。
- 需要工程师决策：通知是否也要覆盖轮询路径（建议：轮询路径同样检测过渡，或在轮询结果合并时检测）。

### 重复通知风险（防抖/去重）
- 后端**共享进度轮询每 1 秒广播一次**，且调度器另有 _on_progress 回调广播（backend/app.py 第 116-148 行）——同一终态可能被推多次。
- 一旦 item 进入终态（completed/failed），后续消息仍会包含它。**必须按 task_item_id 去重**：通知一次后记住该 id，或依赖"旧状态已是终态则不再触发"（方案 A 天然满足，因为第二次消息来时旧状态已经是 completed/failed）。

## 2. 前端 api.ts ConfigResponse 扩展

### 现状（frontend/src/lib/api.ts 第 53-59 行）
```ts
export interface ConfigResponse {
  download_dir: string;
  concurrency: number;
  chunk_size: number;
  metadata_format: string;
  onboarding_done: boolean;
}
```

### 需要新增的字段
| 字段 | 类型 | 说明 |
|---|---|---|
| notification_enabled | boolean | 通知总开关 |
| sound_enabled | boolean | 音效开关 |
| sound_choice | string | 音效选择（可选值待定，如 "default"/"ding"/"bell" 等） |
| sound_volume | number | 音量（建议 0.0-1.0 浮点，SettingsPanel 滑块展示为百分比） |

### 同步点
- updateConfig 已用 Partial<ConfigResponse>（第 208 行），新增字段自动支持部分更新，**无需改 updateConfig 签名**。
- 后端返回的 JSON 中若字段缺省，前端类型会不匹配（运行时 undefined）。建议后端 GET /config 始终返回全部字段。

## 3. 后端 backend/api/config.py 扩展

### 现状（backend/api/config.py 第 20-37 行）
- ConfigResponse：download_dir, concurrency, chunk_size, metadata_format, onboarding_done
- UpdateConfigRequest：以上全部可选

### 需要新增
- ConfigResponse 新增：notification_enabled: bool、sound_enabled: bool、sound_choice: str、sound_volume: float
- UpdateConfigRequest 新增同样 4 个字段（xxx: bool | None = None 风格保持）

### get_config 端点（第 43-55 行）需处理类型转换
**关键点：config 表全部是字符串键值对**（app/models.py 的 Config: key/value 均为 str），读取时要转换：
- notification_enabled：config.get("notification_enabled", "false") == "true"
- sound_enabled：config.get("sound_enabled", "true") == "true"
- sound_choice：config.get("sound_choice", "default")
- sound_volume：float(config.get("sound_volume", "0.7"))

### update_config 端点（第 58-78 行）需处理类型转换
写入时转字符串：
- ctx.config_repo.set("notification_enabled", "true" if req.notification_enabled else "false")
- sound_volume：str(req.sound_volume)
- 注意：UpdateConfigRequest 中字段为 None 时跳过（现有模式已如此）

## 4. app/config.py DEFAULT_CONFIGS 扩展

### 现状（app/config.py 第 25-38 行）
```python
DEFAULT_CONFIGS: dict[str, str] = {
    "download_dir": str(DEFAULT_DOWNLOAD_DIR),
    "concurrency": str(DEFAULT_CONCURRENCY),
    "chunk_size": str(DEFAULT_CHUNK_SIZE),
    "retry_count": str(DEFAULT_RETRY_COUNT),
    "metadata_format": DEFAULT_METADATA_FORMAT,
    "onboarding_done": "false",
}
```

### 需要新增
| 键 | 默认值 | 说明 |
|---|---|---|
| notification_enabled | "true" | 通知默认开启 |
| sound_enabled | "true" | 音效默认开启 |
| sound_choice | "default" | 默认音效名 |
| sound_volume | "0.7" | 默认音量 70% |

可以像现有 DEFAULT_* 常量那样定义常量再聚合进 dict，保持风格一致。

### 数据库迁移注意
- database.init_default_db() 首次初始化时会把 DEFAULT_CONFIGS 插入 config 表（见 app/config.py 注释）。
- **已有数据库（存量用户）不会自动新增这些键** —— 需要确认 database.py 初始化逻辑是否做"缺失键补齐"（upsert）。若没有，GET /config 的 .get(key, default) 兜底也能工作，但 reset 后才有值。工程师需核对 app/database.py 的插入策略。

## 5. SettingsPanel 加载/保存流程与 SectionCard 复用

### 加载流程（SettingsPanel.tsx）
1. 组件挂载 -> useEffect(() => { loadConfig(); }, [])（第 95-97 行）
2. loadConfig()（第 82-93 行）：调用 api.fetchConfig() -> setConfig(cfg) -> 提取 setConcurrency(cfg.concurrency) 单独存 state
3. loading 期间显示 Loader2 旋转图标（第 126-132 行）

### 保存流程
- **并发数**：handleSaveConcurrency（第 99-111 行）-> api.updateConfig({ concurrency }) -> 成功后本地 setConfig({...config, concurrency}) + toast
- **下载目录**：handlePickDirectory（第 113-124 行）-> tauri 目录选择 -> api.updateConfig({ download_dir: dir })
- **重置**：api.resetConfig() -> 重新 loadConfig（第 280-291 行）

### 关键模式（工程师可直接复用）
- **配置放在 config state 对象中**，单个子更新用 setConfig({...config, key: value})
- **保存是"手动触发 + 立即生效"**（无自动保存/防抖），每个控件独立保存
- **SectionCard 组件**（第 25-61 行）是本文件内定义的通用折叠卡片，签名：
  SectionCard({ icon, title, description, open, onToggle, children })
  - 新增"通知设置"区域 = 在下载设置卡片之后/元数据之前插入一个新 <SectionCard>，icon 可用 Bell/Volume2（lucide 已引入），title "通知设置" 或 "通知与音效"
  - 卡片内容区可放：开关（checkbox 或 switch 风格）、音效选择（下拉/按钮组）、音量滑块（复用 concurrency 的 range input 样式，第 186-195 行）
- openSection state 决定当前展开项（第 71 行），新增卡片需有唯一 section id（如 "notify"）

### 现有 UI 基础
- 没有现成 switch 组件，但 concurrency 用原生 <input type="range"> 自定义样式（accent-purple-500）——音量滑块可完全复用该样式
- checkbox 用原生 <input type="checkbox"> + accent-purple-500（metadata_format 处同款）
- toast 反馈用 useToastStore().addToast(message, type)
